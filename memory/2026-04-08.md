## 重要学习点

### epub文件结构
- 本质是zip压缩包（可用unzip解压）
- 核心文件：
  - `META-INF/container.xml` - 指向内容清单
  - `OEBPS/content.opf` - 书籍元数据与文件清单
  - `OEBPS/toc.ncx` - 目录结构
  - `OEBPS/story-*.xhtml` - 各章节内容

### 处理繁体中文
- 使用 `sed 's/<[^>]*>//g'` 去除HTML标签
- 注意特殊字符（、。「」）
- grep过滤空行

### 观点提炼方法论
1. **识别关键时刻**：转折点、冲突、决策
2. **提取数据对比**：量化的冲击力（如：550亿 vs 520亿）
3. **捕捉金句**：简洁有力的原文段落
4. **分析深层逻辑**：为何重要？给我们什么启发？

- 没有 skill：AI 只能提供理论建议（"纸上谈兵"）
- 有了 skill：AI 能真正执行任务（"真刀真枪干活"）

### Skill 的结构
```
~/.openclaw/skills/pdf/
├── SKILL.md          ← 核心！告诉 AI "怎么做"
├── scripts/          ← 实际执行的工具脚本
│   ├── merge.py
│   ├── split.py
│   └── ocr.py
├── references/       ← 参考文档、示例
└── README.md         ← 给人类看的说明
```

### 运作流程
```
用户：「帮我把这3个PDF合并」
  ↓
AI 分析关键词【合并、PDF】
  ↓
系统检查已安装的 skills
  ↓
发现 pdf skill ✅
  ↓
读取 SKILL.md 中的"合并 PDF"任务步骤
  ↓
执行：找文件 → 运行合并脚本 → 生成结果
  ↓
告知用户：「已完成！文件在 ~/Desktop/merged.pdf」
```

### Skill 的三个等级

**🟢 Level 1：基础工具型**
- 例子：`pdf`、`docx`、`csv-excel-processor`
- 作用：处理具体文件格式
- 收益：一句话完成文件操作

**🟡 Level 2：智能创作型**
- 例子：`frontend-design`、`ui-ux-pro-max`、`html-slides`
- 作用：创造新内容（设计页面、生成 PPT）
- 收益：从"文件处理助手"升级到"创意伙伴"

**🔴 Level 3：元能力型**
- 例子：`skill-creator`
- 作用：创建其他 skills（"造工具的工具"）
- 收益：可以定制专属的新 skill

## 三阶段工作流升级 (16:33-16:41)

**用户新需求：** "我还想要阅读报告的 pdf 版本，以后先产出 html 版本，我跟你确认好定稿版本后，再产出 md+pdf 可以吗"

**核心理念：** 先快速迭代（HTML），确认满意后批量生成所有格式

### 🎯 新的三阶段工作流

#### 阶段 1：HTML 初稿（快速迭代）
**目的：** 快速预览，反复修改直到满意

**流程：**
1. 解析书籍内容（epub/PDF）
2. 生成 HTML 版本（绿色主题 + 响应式）
3. 在浏览器中打开查看
4. 用户审阅 → 需要修改？→ 🔄 调整后重新生成
5. 满意了 → 进入阶段 2

**优势：**
- ✅ HTML 即时可见，视觉效果好
- ✅ 修改快速，无需维护多个格式
- ✅ 可以反复迭代（成本低）

#### 阶段 2：定稿后批量生成（MD + PDF）
**触发条件：** 用户确认"定稿了"

**自动生成：**
1. Markdown 版本 → Obsidian 用
2. PDF 版本 → 打印/分享/存档用

**最终产出：**
```
study notes/
├── 《书名》阅读指南_绿色版.html   ← 浏览器查看
├── 《书名》阅读指南.md            ← Obsidian 用
└── 《书名》阅读指南.pdf           ← 打印/分享/存档
```

#### 阶段 3：更新索引
- 更新 `README.md`，添加新书条目（含3个格式链接）
- 刷新 Obsidian 索引（`Cmd + R`）

### ⏱️ 时间估算
- 阶段 1（HTML + 迭代）：10-20 分钟
- 用户审阅：5-10 分钟
- 阶段 2（MD + PDF）：3-5 分钟
- 阶段 3（更新索引）：1-2 分钟
- **总计：~20-40 分钟**

### 📋 迭代示例
```
第一轮：生成 HTML 初稿 → "改一下第三章的措辞"
第二轮：重新生成 HTML v2 → "思考篇章加个投资案例"
第三轮：重新生成 HTML v3 → "完美！定稿了！"
批量生成：生成 MD + PDF → 完成！✅
```

### 🎯 关键优势
**为什么先生成 HTML？**
1. 视觉反馈最快（浏览器即看）
2. 修改成本低（只维护一个文件）
3. 效果最直观（绿色主题、卡片布局）
4. 适合反复迭代

**为什么定稿后才生成 MD + PDF？**
1. 避免重复劳动（不用每次改三个文件）
2. 确保版本一致（最终三个格式内容相同）
3. 节省时间（只在满意后批量生成）
4. 保持灵活性（初稿阶段可大胆调整）
