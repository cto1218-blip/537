## 🔴 中東追蹤儀表板 Cron 任務連續失敗

### 問題時間線
- **08:00 任務失敗**：只執行到步驟2（構建JSON），未執行 Python 腳本和部署
- **09:00 任務失敗**：模型說「需要先檢查會話狀態」然後什麼都沒做

### 根本原因診斷
1. **Payload 設計缺陷**：
   - 原始指令寫成「建議步驟」而非「強制命令」
   - 模型會「思考需要做什麼」而不是「直接執行」
   - Isolated session 的模型傾向評估而非行動

2. **技術細節**：
   - 模型在輸出 JSON 後誤以為任務完成
   - 或者陷入「準備階段」無法進入執行
   - 缺少「立即行動」的明確指令

### 解決方案（09:20 實施）
將所有 24 個 cron 任務 payload 簡化為：
```
中東局勢追蹤頁面更新（立即執行，不要思考）

1. 搜索 Israel Iran Lebanon ceasefire
2. 搜索 oil price WTI Brent
3. 寫 JSON 到 /tmp/me.json
4. 執行腳本 + 部署
5. 回覆 ✅

禁止 read HTML，禁止只輸出不執行
```

- ⏳ 待批量更新剩餘 22 個任務

### 關鍵教訓
**Cron payload 設計原則**：
1. **極簡指令**：少於10行，禁止解釋性文字
2. **強制動作**：用「執行X」而非「你可以執行X」
3. **禁止思考**：明確寫「立即執行，不要思考」
4. **檢查點少**：避免「先做A，如果成功再做B」的條件邏輯
5. **單一目標**：一個任務只做一件事

**特別注意**：
- Isolated session 不會保留上下文，每次都是「新人」
- 不要期望模型「記得」之前的步驟
- 每個指令都要當成「給陌生人下命令」
